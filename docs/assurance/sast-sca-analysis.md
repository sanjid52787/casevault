## Tool limitations, false positives and false negatives

- SpotBugs/FindSecBugs and Semgrep are pattern/dataflow analyses. They cannot prove tenant isolation, BOLA/IDOR
  resistance, separation of duties, correct state transitions, or whether a business workflow is abusive.
- Gitleaks detects recognisable secret patterns but cannot prove a value is active, catch every custom secret
  format, or remove values from Git history. The historical allow-list should be reviewed if the commit changes.
- Dependency-Check maps components to public CVEs and can suffer CPE false matches, delayed NVD data and an
  incomplete local database. It cannot assess insecure configuration, malicious-but-not-yet-reported packages,
  or dependency provenance by itself. This run is incomplete without an NVD API key.
- CycloneDX inventories resolved components but does not determine exploitability, licence compatibility or
  runtime reachability. Licence metadata can be incomplete or dual-licensed and therefore receives human review.
- CodeQL runs in GitHub Actions; until a workflow run is retained, this repository has configuration evidence,
  not execution evidence. None of these tools replaces the HTTP authorisation matrix, end-to-end tests, manual
  secure code review, proxy/TLS testing or production configuration review.
